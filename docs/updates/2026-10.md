## U-20261001-01 · 2026-10-01 · je_action_core: the shared action executor · #migration #L-6 #X-12

- **What**: workspace L-6 asked for one action executor in place of four copies. APITestka, LoadDensity, MailThunder and FileAutomation each carried their own executor, package manager, callback executor, action-file reader and socket server, and every component had drifted between them. A read-only comparison of the four (and WebRunner) set the scope.
  - The owner chose a new, dependency-free package published to PyPI, with all four projects moving to it.
  - This package holds one implementation of each component. Every difference between the projects is a setting:
    - **executor**: document key and legacy keys, raise or return `{}` on an empty list, legacy or strict action parsing, plain or indexed record keys, a `prepare` rewrite, and a reporter (logger, console, or custom);
    - **registry**: functions only, or any callable;
    - **package manager**: prefixed or bare member names, the predicates, a name check, which errors are logged, and the WebRunner-style package gate, which can be switched on or off;
    - **callback executor**: legacy or strict checks, raise or return `None`;
    - **JSON files**: exception class and message templates;
    - **socket server**: payload validation, which errors get a reply, and what happens to an oversized payload.
  - LoadDensity's gevent socket server and FileAutomation's authenticated server stay in those projects (`progress.md` #2).
- **Result / numbers**: 83 tests (one module per piece, plus the workflow pinning checks from APITestka) pass on Python 3.10. ruff passes with `E,F,W,C90,B,PL,SIM,I,S,N,UP` at 120 columns. zizmor reports only informational findings.
- **Files**: `je_action_core/`, `test/`, `pyproject.toml` (version `0.0.0`, no dependencies), `.github/` (CI matrix 3.10–3.14 on three systems, publish on `main`, Dependabot on `dev`), `README.md` + `README/README_zh-TW.md` + `README/README_zh-CN.md`, `architecture.md`, `CLAUDE.md`, `progress.md`.

## U-20261001-06 · 2026-10-01 · Socket server: template handler, framing, TLS, two auth dialects · #change #socket-server

- **What**: the first step of `progress.md` #2. Everything LoadDensity's and FileAutomation's servers do differently is now part of the core, so they can move onto it (next steps).
  - `ActionRequestHandler` is a template with overridable steps: `secure`, `read_request`, `decode`, `process`, `run_text`, `run_document`, `reply_failure`, `on_quit`, `write`.
  - `SocketServerSettings` gains:
    - `framing` (`RAW`, or a 4-byte length prefix with a 1 MiB cap and one frame per reply line);
    - `decode_errors`;
    - `messages` (`ReplyMessages`: templates for records, each failure stage, an undecodable request, the quit reply, the authentication refusals and the log line);
    - `secret` / `auth_prefix`, `tls_context` (with the helper `server_tls_context`, TLS 1.2 or later) and `recv_timeout`.
  - `ActionTCPServer` gets `close_event` and `request_stop()`, which stops `serve_forever` from a helper thread.
  - `socket_auth.py` adds `SecretHeaderRequestHandler` (a `<prefix><secret>` first line) and `EnvelopeTokenRequestHandler` (a `{"token", "command" | "op": "quit"}` envelope), with constant-time `secret_matches`.
  - The defaults keep APITestka's and MailThunder's wire format byte for byte: `"{value!s}"` / `"{error!s}"` match their `str()`, a reply line is one `sendall` of text plus newline (the same bytes as their two `sendto` calls), and quit sends no reply.
- **Result / numbers**: 106 tests pass. The new `test/test_socket_dialects.py` drives the handlers with a fake connection and covers framing, every failure template, decoding, quit, the log line, `recv_timeout`, TLS wrapping and a failed handshake, and both dialects with LoadDensity's and FileAutomation's exact messages. ruff passes.
- **Files**: `je_action_core/socket_server.py`, `je_action_core/socket_auth.py`, `je_action_core/__init__.py`, `test/test_socket_dialects.py`, `README.md` + `README/README_zh-{TW,CN}.md`, `architecture.md`.

## U-20261001-08 · 2026-10-01 · Executor hooks for WebRunner: attempt, failure records, numbered keys, collect · #executor #webrunner

- **What**: the first step of `progress.md` #3. WebRunner's executor differs from the other four in where it wraps an action and what it records. The core gains:
  - **`ActionExecutor.attempt(action)`**: the one place every action passes, for retries or a span around the whole action, binding included. `run_one`, `execute_action` and `collect_action_results` all go through it.
  - **`ExecutorSettings.failure_record`**: what a failed action records. The default `repr_failure` keeps `repr(error)`.
  - **`ExecutorSettings.duplicate_keys`**: `DuplicateKeys.REPLACE` (the default, as before) or `NUMBER`, where a repeated key becomes `<key> #2`, `#3` … (`unique_record_key`).
  - **`ActionExecutor.collect_action_results(action_list)`**: returns `(records, failed keys)` without reporting the records.
  - **`ExecutionReporter.on_start(action_list)`**: sees the list as given, before it is checked.
  - **`ActionListSource`**: `ExecutorSettings.rules` takes anything with `extract(action_list)`, not only `ActionListRules`.
- **Kept**: the defaults change nothing for the four projects. Each ran its full suite against this tree: APITestka 744, LoadDensity 1189, MailThunder 120, FileAutomation 786, all passed. FileAutomation keeps its own loop.
- **Also**: `callback.py`'s legacy `**param` call gets a `cast`, so `mypy je_action_core` reports no issues. A non-mapping still fails in the call, as before.
- **Docs**: README (three languages) `executor` row; `architecture.md` §2, §4 (execute flow) and §5 (wrapping every action).
- **Result / numbers**: 114 tests passed (`test/test_executor_hooks.py` is new). `ruff check` and `mypy` are clean.
- **Files**: `je_action_core/executor.py`, `je_action_core/reporting.py`, `je_action_core/callback.py`, `je_action_core/__init__.py`, `test/test_executor_hooks.py`, `README.md` + `README/README_zh-{TW,CN}.md`, `architecture.md`.
