## U-20261001-01 · 2026-10-01 · je_action_core: the shared action executor · #migration #L-6 #X-12

- **What**: workspace L-6 asked for one action executor in place of four copies. APITestka, LoadDensity, MailThunder and FileAutomation each carried their own executor, package manager, callback executor, action-file reader and socket server, and every component had drifted between them. A read-only comparison of the four (and WebRunner) set the scope.
  - The owner chose a new, dependency-free package published to PyPI, with all four projects moving to it.
  - This package holds one implementation of each component. Every difference between the projects is a setting:
    - **executor**: document key and legacy keys, raise or return `{}` on an empty list, legacy or strict action parsing, plain or indexed record keys, a `prepare` rewrite, and a reporter (logger, console, or custom);
    - **registry**: functions only, or any callable;
    - **package manager**: prefixed or bare member names, the predicates, a name check, which errors are logged, and the WebRunner-style package gate, which can be switched on or off;
    - **callback executor**: legacy or strict checks, raise or return `None`;
    - **JSON files**: exception class and message templates;
    - **socket server**: payload validation, which errors get a reply, and what happens to an oversized payload.
  - LoadDensity's gevent socket server and FileAutomation's authenticated server stay in those projects (`progress.md` #2).
- **Result / numbers**: 83 tests (one module per piece, plus the workflow pinning checks from APITestka) pass on Python 3.10. ruff passes with `E,F,W,C90,B,PL,SIM,I,S,N,UP` at 120 columns. zizmor reports only informational findings.
- **Files**: `je_action_core/`, `test/`, `pyproject.toml` (version `0.0.0`, no dependencies), `.github/` (CI matrix 3.10–3.14 on three systems, publish on `main`, Dependabot on `dev`), `README.md` + `README/README_zh-TW.md` + `README/README_zh-CN.md`, `architecture.md`, `CLAUDE.md`, `progress.md`.
- **Open items**: `progress.md` #1 (first PyPI release), #2 and #3.

## U-20261001-02 · 2026-10-01 · ActionListRules.from_document is public · #change #action-list

- **What**: MailThunder's socket server checks a payload before running it, and it needs the document's list exactly as found: under the key, else under a legacy key with a `DeprecationWarning`, else `None`. That lookup was `_from_document`. It is now `from_document(document, stacklevel=2)`. `extract` passes the stack level that points the warning at the caller of `execute_action`, while a direct caller gets the warning pointed at its own caller.
- **Result / numbers**: 84 tests pass. The new test checks the unchecked return value, `None` for a missing key, and that the warning points at the caller.
- **Files**: `je_action_core/action_list.py`, `test/test_action_list.py`.

## U-20261001-03 · 2026-10-01 · add_package_to_executor returns None again · #bugfix #package-manager

- **What**: `PackageManager.add_package_to_executor` and `add_package_to_callback_executor` returned how many members they registered. All four projects returned `None`. Since the method is an action command, a project moved onto the core would have changed that action's record from `None` to a number. Both methods return `None` again.
  - The new `check_and_add(package, target)` applies the gate and returns the count, for FileAutomation's loader, which does return one. `add_package_to_target` still returns the count.
  - APITestka and MailThunder, already moved, pick this up with their next pin bump.
- **Result / numbers**: 85 tests pass, including a new test of `check_and_add` and of the `None` return.
- **Files**: `je_action_core/package_manager.py`, `test/test_package_manager.py`.

## U-20261001-04 · 2026-10-01 · The package ships py.typed · #change #typing

- **What**: the package is fully annotated, but it had no PEP 561 `py.typed` marker. Type checkers therefore treated every import from it as `Any`. FileAutomation's mypy run would not have checked its subclasses against the core. `je_action_core/py.typed` now ships in the wheel (`[tool.setuptools.package-data]`).
- **Result / numbers**: 86 tests pass; the new test checks the marker is there. The built wheel contains `je_action_core/py.typed`. FileAutomation's `mypy automation_file`, with the package installed normally, reports no issues.
- **Files**: `je_action_core/py.typed`, `pyproject.toml`, `test/test_public_api.py`.
